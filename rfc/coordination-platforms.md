# Native coordination platform contracts

The ownership protocol, authority, and snapshot journal are shared across platforms. Native adapters supply scope identity, retained storage, nonblocking bookkeeping synchronization, and incarnation-qualified operation-owner lifetime evidence. Each adapter must satisfy the same [acceptance histories](coordination.md#acceptance-histories).

## Current implementation and activation

| Target  | Current shared backend                                            | Current mode selection                             | Native activation gate                                                                      |
| ------- | ----------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Linux   | Private tmpfs journal, pinned sibling anchor, `flock` owner slots | Opt-in shared coordination                         | Linux subprocess, namespace, recovery, and performance acceptance                           |
| Windows | Private NTFS/ReFS journal, pinned anchor, exclusive owner handles | Opt-in implementation; native acceptance pending   | Native process/session/crash acceptance and retained accounting across reboot               |
| macOS   | Root-qualified tmpfs journal and pinned anchor                    | Opt-in implementation; native acceptance pending   | Native tmpfs, sandbox, root transition, inherited ownership, sleep/wake, and resource tests |
| FreeBSD | Root-qualified tmpfs journal and pinned anchor                    | Opt-in for compatible roots; capability rejection  | Retained tmpfs discovery, jail/capability identity, inherited owner locks                   |
| illumos | Zone-qualified tmpfs journal and pinned anchor                    | Opt-in shared coordination                         | Native zone transitions, privilege restrictions, and resource acceptance                    |
| Solaris | Unavailable                                                       | Required errors; Auto reports unsupported fallback | Verified lifetime primitive and zone-local scope on the exact supported release             |

ProcessOnly remains the default everywhere. `tests/coordination_policy.rs` exercises mode selection, including explicit unsupported-platform outcomes. The existing CI matrix runs the portable tests on native Windows and macOS runners and FreeBSD/OmniOS VMs. Those jobs run each implemented adapter's process histories as part of its native release acceptance. Solaris cross-compilation checks API availability; native Solaris execution is a separate gate.

No port may introduce a version-qualified rendezvous, reset retained debt after the final participant exits, or start a keeper process. Configurations and generations remain authoritative. A joining participant with stricter local limits still requires permission from both governors.

## Windows

Windows distinguishes per-session and global kernel-object namespaces. Creating a global file mapping from an ordinary client session requires `SeCreateGlobalPrivilege`; the global namespace is unavailable to Windows Store apps. This rules out making privileged global mapping creation a discovery prerequisite. [Kernel object namespaces](https://learn.microsoft.com/en-us/windows/win32/termserv/kernel-object-namespaces).

The port contract is:

- Qualify the scope by the effective security identity and the selected session/container boundary. Define a deterministic name independent of executable and crate version. Apply a restrictive DACL to every coordination object and validate existing objects before use.
- Keep the accounting journal in verified host-local retained storage. A paging-file-backed named mapping alone is insufficient: Windows can release its backing after all handles close. A mapping may cache a retained journal, with generation and object-identity checks on reopening. [Creating named shared memory](https://learn.microsoft.com/en-us/windows/win32/memory/creating-named-shared-memory).
- Acquire bookkeeping with a nonblocking `LockFileEx` byte-range lock on the pinned anchor. An independent open must conflict even in the same process. Recover the journal after acquiring exclusion, including after writer death. Bookkeeping lock release never proves operation-owner exit. The lock byte is outside the anchor header; physical ownership uses separate exclusive file handles. [Windows file locking](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex).
- Bind participants to identity-checked owner-slot files opened for read/write with no sharing. Reclamation must successfully reopen the same file with conflicting data access while holding bookkeeping exclusion. Attribute-only opens are insufficient because sharing restrictions do not cover attribute access. Native tests must establish retention through duplicated and inherited handles; a failed open never proves owner exit. This design also permits a newly started participant to recover after every earlier process exits, without requiring it to have cached their process handles. [CreateFile sharing rules](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew).
- Select a common monotonic clock and bind its epoch to retained scope identity. Reboot or session recreation must not interpret an older epoch as current elapsed time or permit old and new authorities simultaneously.
- On a reboot, retain the existing journal generation and debt. Rebase the new boot's performance counter at the authority's last committed logical timestamp; the downtime and time between that last commit and the first reopen do not refill budgets. Publish the new epoch and signed counter offset in the same recoverable journal as the accounting. Every subsequent connection reuses this exact mapping, including after all handles close. Refill resumes as the new boot's counter advances. Transactions clamp individual readings to committed authority time without changing the mapping.
- Reject remote or redirected storage, unsafe ACLs, conflicting object types, and unavailable sandbox access. Never retry an unsafe scope under a new name.

Native tests must cover ordinary unprivileged discovery, independent sessions, duplicated/inherited handles, bookkeeping-thread death with a live I/O thread, complete process death, retained debt after every mapping closes, object replacement, and AppContainer denial.

`src/coordination/windows/handles.rs` implements the file primitives. It preserves the complete 64-bit volume serial and 128-bit file ID, rejects reparse points and hard links, and pins the expected owner file through the conflicting data-open probe. A missing or replaced file is an error; only successful exclusive reopening establishes final close. The returned handle retains exclusion through the caller's recovery commit.

`relative.rs` resolves an absolute drive root once, then opens each directory component against its pinned parent handle. Ancestors deny delete sharing while retained. Child creation and owner recovery use `NtCreateFile` with a single relative component, synchronous handles, and reparse rejection; neither reopening nor creation truncates existing accounting. Stream syntax, traversal, and ambiguous trailing characters are rejected before opening. The authority can retain these parent pins instead of resolving its absolute path again for every transaction. [Relative object names and reparse rejection](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_object_attributes).

`tests/coordination_windows.rs` exercises duplicate retention, inherited ownership after original-process death, missing/replaced/hard-linked slots, unrelated descriptor closure, and four actual journal-writer kills. The last history keeps a separate operation owner alive and verifies retained journal accounting after all bookkeeping handles close. The complete suite passes natively in the Windows x64 and ARM64 CI matrix. `tests/coordination_cohorts.rs` adds the same held-read process cohorts and integrated owner-death histories used on Unix; independent-session and AppContainer acceptance remain open.

`coordination::windows::Scope` connects these primitives to the shared journal and governor. Discovery uses `SHGetKnownFolderPath` with the effective user's token, independent of environment variables and executable/version/session names. A retained sibling anchor binds the user SID, boot-qualified clock, parent directory, state directory, journal identity, and generation. Only unpublished initialization may be restarted; an existing committed account is reopened and checked against the requested limits. Owner records keep the full 128-bit file ID, qualified by the root volume recorded in the anchor. Final-close recovery retains exclusive owner handles through the journal commit and can transfer a reclaimed slot directly to its next participant.

Windows and Unix share the `Client`, preparation, physical-completion, and bounded deferred-settlement implementation in `client.rs`. The same governor binding composes local and shared reservations on both. Native Windows fixtures cover generation/charge retention after every handle closes, owner-slot reuse, replacement/configuration rejection, and actual Scan listing and lazy reads.

`security.rs` creates objects with a protected owner-only DACL and validates existing objects without changing their ACLs. Missing, null, inherited, broadened, or mismatched-owner descriptors are invalid state, rather than an unavailable result that would permit Auto fallback. The effective thread token takes precedence over the process token. User SID, session, authentication identity, token identity, and token revision fence a captured context when impersonation or token modification changes it. Authentication identity does not select the persistent scope name, so a new login cannot mint a fresh budget.

Descriptor-policy and same-user impersonation tests pass under Wine 11.20. The file-based suite now rejects Wine storage: its `server/file.c` reconstructs file security descriptors from Unix mode bits and does not preserve the protected-DACL flag. File creation, reopening, and ACL-mutation histories therefore require native Windows execution; there is no weaker Wine permission path. [Wine 11.20 source](https://dl.winehq.org/wine/source/11.x/wine-11.20.tar.xz).

`storage.rs` validates the opened file or directory before its ACL is accepted. A successful device-information query must identify a local disk or disk-filesystem device; a failed query never establishes locality. The same handle must report writable NTFS or ReFS with persistent ACLs and file-ID support. This excludes remote devices even when their advertised filesystem name and capabilities match. [Device information](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_file_fs_device_information), [volume information by handle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumeinformationbyhandlew).

`clock.rs` uses the performance counter with integer nanosecond conversion and a retained epoch containing the boot-entry GUID, kernel boot sequence, and counter frequency. The boot-entry GUID alone does not qualify a startup. Malformed headers and incompatible frequencies are rejected without resetting accounting. The immutable anchor retains the creation epoch; the journal stores the current epoch and signed logical offset together with the retained budgets and ownership. A boot transition can move the raw counter either above or below the retained logical timestamp. Only that transition chooses an origin; reopening during the same boot reuses it. A changed persisted mapping fences an existing connection before accounting. Cross-thread counter readings can differ by a tick, so accounting clamps a reading to committed time without moving any connection's origin. [Performance counters](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps), [kernel boot sequence](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-kuser_shared_data).

Counter-only snapshots retain format 2. Windows publishes its mapping in format 3, migrating a retained format-2 snapshot under bookkeeping exclusion without changing its generation, balances, or owners. Readers that do not support format 3 fail explicitly before admission. Byte-interruption tests cover both first publication and another boot transition during journal-slot reuse, preserving the complete old or new authority. Native Windows fixtures cover simulated boot changes, independent connections, reopening after all handles close, and stale-mapping fencing; actual reboot acceptance remains open.

## macOS

Darwin `flock` supports nonblocking acquisition. Duplicated and fork-inherited descriptors refer to the same lock; an explicit unlock through one reference affects the others. The owner-slot design therefore requires close-only lifetime release, while bookkeeping uses an explicit scoped unlock. [Apple's `flock(2)` manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/flock.2.html).

`coordination::macos::Scope` uses the shared Unix journal and pinned anchor on an administrator-mounted tmpfs at `/var/run/tree-fucker`. The adapter verifies the filesystem type, private effective-user ownership, and filesystem root identity. Native tmpfs is available through `mount_tmpfs` on macOS 11 and later; its retained objects and the kernel monotonic clock share a boot lifetime. [macOS `mount_tmpfs(8)`](https://man.freebsd.org/cgi/man.cgi?manpath=macOS+13.6.5&query=mount_tmpfs&sektion=8).

The adapter participates in the same governor, diagnostics, independent-process tests, interrupted-publication tests, and Cargo benchmarks. Filesystem roots that expose incompatible retained authorities cannot fall back to a fresh local budget. Unknown domain identity remains participant-private beneath the common aggregate envelope.

`tests/coordination_macos.rs` adds a dedicated subprocess that enters a filesystem-denying sandbox after joining. It asserts explicit pre-join unavailability, post-join fencing without local charges, and no journal mutation. A privileged root-transition subprocess verifies that an existing governor and an Auto reopen reject the incompatible root, while a separately requested root-local authority retains its charges. The workflow provisions tmpfs and runs these tests and process benchmarks on both Mac architectures. Both architectures pass the native integration suite, including root and sandbox transitions. The dedicated acceptance workflow also collects aggregate resources. Real sleep/wake remains a separate gate: macos-26 rejects system sleep, and macos-26-intel records no kernel sleep/wake transition. The physical test requires a sleep-capable runner selected through COORDINATION_SLEEP_RUNNER or the workflow dispatch input.

## FreeBSD

FreeBSD `flock` provides nonblocking acquisition and preserves shared lock references across `dup` and `fork`. Its documentation also describes interaction with `fcntl` and `lockf`; the adapter must consistently use one locking interface. [FreeBSD 15.0 `flock(2)`](https://man.freebsd.org/cgi/man.cgi?manpath=FreeBSD+15.0-RELEASE&query=flock&sektion=2).

`coordination::freebsd::Scope` uses the shared Unix tmpfs journal and pinned anchor implementation. Discovery requires an administrator-mounted tmpfs at `/var/run/tree-fucker`; explicit directories must also be on tmpfs. The adapter verifies filesystem type, effective ownership, private permissions, and filesystem root identity before opening retained state. It uses FreeBSD monotonic time within the lifetime of that tmpfs mount. Declared storage domains remain participant-private accounts beneath the shared aggregate envelope.

Host and jail processes with the same filesystem root and effective user may join the same authority: they see the same retained files and kernel monotonic clock. Separate jail names or numeric IDs do not create separate budgets. A different filesystem root is incompatible even if it exposes the original retained directory, and Auto mode must not downgrade this mismatch to process-only governance. A jail with its own root can explicitly create an authority on its own tmpfs view.

FreeBSD deliberately reports zero for the caller's own jail ID in `kinfo_proc`; it is not used as a namespace identifier. [FreeBSD kernel process information](https://cgit.freebsd.org/src/tree/sys/kern/kern_proc.c?id=645743ea99829e6d578cca5a580cf0a4102fb7dd). Root identity and effective user are rechecked on each access. Capability-mode callers receive an explicit unavailable result before joining, and capability entry fences an existing handle. The default kernel policy blocks jail entry while the authority's directory descriptors are open; after those handles close, reopening from a compatible jail preserves the same generation and prior charges.

Native tests hold real FIFO work in one jail and deny dispatch from another under the same physical ceiling. They also verify incompatible-root rejection without journal modification, separate-root local authority retention, host-to-jail charge retention, and effective-user isolation. Owner descriptors remain close-only, and inherited API handles reject post-fork use before touching a process mutex. The shared process suite covers fork/exec/dup lifetime, final-close retention, and interrupted updates.

## illumos and Solaris

These targets have separate lock contracts. Current illumos documents open-file-description locking through `F_OFD_SETLK` and its Linux/BSD-compatible `flock`. Such locks survive duplicated/inherited descriptions and release on the last close. Its POSIX locks instead belong to a process and can disappear when another descriptor for the same file closes. [illumos `fcntl(2)`](https://smartos.org/man/2/fcntl).

`coordination::illumos::Scope` uses nonblocking native `flock`, verified tmpfs, a pinned anchor, and the shared bounded journal. Discovery requires an administrator-created sticky directory at `/var/run/tree-fucker` on tmpfs. Effective user, root identity, numeric zone ID, and the kernel's non-reused zone incarnation qualify the scope. `ZONE_ATTR_UNIQID` is read on each context check, so recreating a zone cannot reuse its previous scope identity merely because its numeric ID repeats. The monotonic epoch and tmpfs storage share a boot lifetime. Domain accounts remain participant-private beneath the aggregate envelope. No POSIX-lock fallback is used.

The referenced Solaris `fcntl` contract describes process-associated record locks that are not inherited across `fork` and are released when a descriptor for the file closes. That contract does not meet the owner-slot invariant. Solaris requires a separately verified description-lifetime primitive or a native process-lifetime design before shared coordination can be enabled. [Oracle Solaris `fcntl(2)`](https://docs.oracle.com/cd/E88353_01/html/E37841/fcntl-2.html).

`tests/coordination_socket_lifetime.rs` evaluates a bound Unix datagram endpoint as an alternative Solaris lifetime primitive. Repeated nonblocking connects send no messages; duplicate and inherited descriptions keep the endpoint alive after the original owner closes or dies. A connected probe does not keep a closed owner discoverable. These histories pass on Linux, FreeBSD, and OmniOS; OmniOS reports `EDESTADDRREQ` for the retained pathname after final close. Solaris cross-compilation passes. The dedicated acceptance workflow boots Solaris 11.4 in a VM and installs the native Rust distribution directly; current rustup cannot lock its settings file on Solaris. This candidate is not yet used by an authority. A Solaris port still requires native evidence, identity/replacement fencing, and a bookkeeping primitive that cannot lose exclusion when an unrelated descriptor closes.

Native acceptance must include independent zones, privilege restrictions, closing an unrelated descriptor to a locked inode, duplicated/inherited ownership, writer death, owner death, final-participant exit, and generation replacement. OmniOS acceptance does not establish Solaris acceptance.

## Evidence required for a port

An adapter's support entry records the exact OS/release, architecture, storage type, security/namespace boundary, clock, lifetime primitive, and native test run. It must run the shared twenty-process ceiling tests with actual held work, all lifecycle cancellation cases, interrupted publication and replay, restart/debt retention, and scope replacement histories. Resource reports include startup/churn, steady contention, blocked work, and idle behavior. A port is ready for release only after those results establish its contract.
