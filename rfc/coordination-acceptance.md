The Tree fixture waits for metadata updates after initial membership completes.

Composed retries distinguish lock and physical contention from refillable budget denials. Shared quarantine reaches Scan during both preparation and start. Traversal emits `Unlisted` for the affected domain and continues with healthy siblings, and lazy reads return `Stuck`. A shared minimum above the caller ceiling returns `ResourceLimited`, including during Scan bootstrap and during initial or resumed Tree command admission. `tests/coordinated_governor/tree_denials.rs` covers Refresh and Load at both admission stages and verifies that a coalesced command with enough remaining budget continues after an older command is rejected. On Linux, the same file has a peer hold stuck work on a shared mount domain. A queued Tree job denied at start and a suspended job denied at resumption both cancel and release their preparations, which leaves the batch free for a healthy domain. Their Refresh commands stay open until the peer settles and complete when the Tree timer fires at the shared quarantine retry deadline. Tree domain health reports `StuckWorker` for the mount domain during the peer's quarantine and clears after the peer settles.

In `tests/tree.rs`, `a_tree_queued_behind_host_capacity_wakes_when_another_holder_releases_it` releases a directly held host slot and asserts that the queued Refresh completes without advancing time. In `tests/resource_safety.rs`, `a_governor_denial_changes_no_obligation_cursor_barrier_or_retry_state` admits a foreground Refresh in the dispatch cycle that finds the background bucket in debt. `tests/coordinated_governor/denials.rs` verifies these outcomes without permitting a retry wait.

Its `shared_quarantine_retry_doubles_to_its_cap_and_resets_on_admission` asserts retry deadlines of 10, 20, 40, 80, 160, 320 and 640 ms, then 1 s twice, across consecutive quarantine denials. It asserts no deadline after the next admission starts and releases. While the domain backs off and the bookkeeping lock is held, the governor refuses an admission with `StuckWorker` and makes no shared attempt. An admission on another domain at the same time succeeds. Its `busy_shared_denial_keeps_the_quarantine_health_report_and_delay` reaches a 40 ms quarantine delay and attempts after that deadline with the bookkeeping lock held. It asserts a `Coordination` denial, a 3 ms retry and `StuckWorker` domain health. It also asserts that the next attempt after the lock retry receives a quarantine denial with an 80 ms delay.

Authority tests separate refillable debt from insufficient ceilings for bootstrap and known domains, retain capacity-capped pricing and preserve the cleanup exemption. The twenty-process Scan cohort records quarantine, then retries lazy reads explicitly after owner settlement. Retry tests cover bounded backoff, stable upcoming deadlines, expired hints, reset after progress, and zero local charging during denied starts and preparations. The measured retry changes reduce contention and churn latency and raise contention CPU. The benchmark baseline records both effects.

## Composed acquisition under bookkeeping contention

`tests/coordination_acquisition.rs` exercises the public `HostGovernor` through the production native authority. A controller holds the actual bookkeeping lock and loads the journal under that exclusion. The test compares the complete authority before and after local actions to check that provisional rollback, completion and duplicate release cannot change shared ownership before a durable commit.

The acquisition matrix covers nine boundaries with background and foreground priority, zero and four optional operations, and bootstrap and known-domain reservations. That makes 72 histories. The boundaries are local preparation denial, dropping local preparation, failed public commit, cancelling shared preparation, local memory rejection at start, a busy shared start, a full shared physical ceiling, physical completion, and completion after a cost report. Contended calls run on deadline-bounded worker threads. For a local rejection, the test checks that shared authorization was never attempted. For a busy start, it checks one native attempt and the rollback of the local physical hold.

Each boundary checks the expected summed local preparations, reserved duration, physical occupancy, cumulative charge and surcharge. It checks them together with the shared preparations, physical occupancy, bootstrap reservation, withheld debt, surcharge and pending settlement count. A surrounding native-clock interval and the authorized reservations bound the shared cumulative charges. A history that never authorizes work must charge exactly zero. Local preparation denial and duplicate start run while bookkeeping is held and must make no native attempt. Duplicate release preserves the same accounting and pending count. The clock bound uses `CLOCK_MONOTONIC` on Unix and integer performance-counter conversion on Windows, because Rust `Instant` may use a different clock than the authority on macOS.

Another 24 histories exercise every release order for three participants with both priorities and lease sizes. One operation has physical ownership and two remain provisional. Each application drops its final client reference after queuing completion or abort. The journal and all three owner lifetimes stay retained until those updates commit. Tree shutdown also runs with bookkeeping held. Logical cancellation retains physical ownership, actual completion releases local capacity, and deferred settlement retains the shared slot until commit. `cargo test --all-features --test coordination_acquisition` reproduces all 97 histories. The native Windows and Unix CI suites include the target.

Windows also runs the common `coordinated_governor` suite, including negotiated initial and resumed listing leases, enrichment allowances, persistent Tree watch and shutdown cleanup, and local and shared start denial. Its directory-rename fencing case runs on Unix only, because live Windows handles prevent that rename. The native Windows replacement test checks the stronger pinning behavior directly.

Process exit discards the process-local mutex state of a local preparation, so a local preparation has no durable publication and no cross-process replay. A successful composed retry uses a fresh operation identity and does not replay a previous public preparation. The binding negotiates lease narrowing before the composed preparation commits and does not call the native `Prepared::narrow` API. The listing and enrichment tests in `coordinated_governor/leases.rs` verify the actual grant delivered to each initial and resumed batch and exactly one read per requested child.

The valid event matrix excludes over-reporting beyond a grant. Section 15.3 requires adapters to honor the per-child lease, and the shared protocol rejects malformed cumulative counts. The authority rejects an over-report, and the client then fences its connection. Clamping its operation count would hide a violation of the adapter contract. Elapsed-time overshoot remains valid, and the authority charges it separately.

`one_and_three_participants_produce_the_expected_accounting_history` in `coordinated_governor/histories.rs` compares the same 28 boundaries for three logical actors that share one governor and for three actors that use three governors. Both traces must match a separately written expected trace. The stream includes background success, foreground failure, preparation and drop, local memory denial, ordinary bootstrap denial, budget-exempt watch cleanup, shared physical denial and retry, deferred settlement, and duplicate start and release. At every boundary, the test compares the summed local preparations, reserved duration, physical occupancy, charge and surcharge against the shared preparations, physical occupancy, cumulative charge and surcharge, bootstrap reservation, withheld debt and pending settlement count. The equality check skips the participant count and the per-process bucket levels, which differ between the topologies by construction. The test does not use native refill levels as a deterministic oracle.

The equivalence fixture prices bootstrap work at one hour and gives each completed operation that same duration on the caller's manual clock. The local estimator samples therefore stay identical across both topologies, and the real native occupancy stays below each reservation. A prepared two-estimate holder fills the shared bootstrap cap. Ordinary foreground admission is then denied, and watch cleanup succeeds and raises the held reservation to three estimates. This proves the cleanup exemption while another allowance is exhausted, including when the earlier denial belongs to the same participant. Under held bookkeeping, completion changes local ownership but leaves one shared physical record and one pending settlement. Draining retires both exactly once.

`coordinated_governor/lifecycle.rs` checks the public Scan and Tree completion paths. `cancelling_a_running_composed_scan_listing_keeps_both_slots_until_physical_completion` uses a physical-start barrier and retains both slots after logical cancellation until the adapter returns. A session that completes successfully despite cancellation owes no surcharge. A session that reports cancellation owes exactly one surcharge to each authority under section 13.1. `cancelling_a_scan_waiting_for_peer_physical_capacity_retires_its_preparations_uncharged` shows that no directory read occurred, retires both preparations, and leaves the peer's physical ownership and exact committed charge intact.

`dropping_the_last_governor_with_started_work_settles_one_shared_failure` exercises final binding destruction while physical ownership is still held. All participants and holds retire, one shared failure surcharge remains, and a later successful participant does not repeat it. `a_failed_foreground_tree_refresh_is_surcharged_once_by_each_authority` asserts the foreground origin of the dispatched grant and both surcharges through duplicate release and shutdown. `a_failed_scan_lazy_read_is_surcharged_once_by_each_authority` keeps both surcharges unchanged through later successful reads and Scan drop. The background Tree failure and lost-worker test also checks the surcharge totals of both authorities.

## Portable native process cohorts

`tests/coordination_cohorts.rs` runs the same three twenty-process histories on Linux, FreeBSD, illumos, macOS and Windows. Each independent process joins the authority and blocks in a kernel pipe read inside an admitted callback. An independently locked counter records actual callback entry and completion, and the test does not use ledger occupancy as its oracle. The controller holds two calls past the stuck threshold and checks that no third callback entered. It then releases every pipe and verifies that all participants and reservations retire while the generation and charges survive reopening every authority handle.

The cohorts exercise the native Bootstrap, LazyRead and WatchRelease operations, real `Scan::read`, and a mix of Scan bootstrap, lazy reads and Tree watch cleanup. A companion crash history kills one of two held owners, verifies that the authority recovers only its slot, and starts a replacement while the other process stays blocked. That history runs through each of the three API fixtures. If a parent assertion fails, the test kills and waits for the child processes. Readiness and completion have bounded deadlines. The full native CI suite runs these tests. `cargo test --all-features --test coordination_cohorts` reproduces them.

## FreeBSD native acceptance

The shared Unix backend runs on FreeBSD 15.0-RELEASE-p14 amd64 under QEMU/KVM, with an administrator-mounted tmpfs and Rust nightly 1.101.0 (2026-10-19). After the compatible jail support landed, the full suite and four explicit privileged acceptance cases pass. The privileged cases are same-root jail contention, host-to-jail charge retention, different-root rejection with local authority creation, and effective-user isolation. Native Clippy with warnings denied and rustdoc with warnings denied pass. `target/benchmarks/freebsd-jail-full.log` records the complete run.

The process histories include all three twenty-application cohorts under a shared physical ceiling of two, inherited owner descriptions, stopped and killed owners, retained debt, and sixty interrupted journal transactions. The effective-user test launches a process as UID 65534, verifies a real admitted file read and a retained charge, and checks that another effective user cannot join its private scope.

Native `coordination`, `coordination_processes` and `coordination_processes_alloc` smoke runs pass. The process benches cover all six scenarios under local and shared governance, and idle workers report zero bookkeeping accesses and zero allocations. `target/benchmarks/freebsd-jail-bench.log` records the benchmark run after the jail support landed. The [repository VM helper](../benchmarks/README.md#local-freebsd-acceptance-vm) reproduces provisioning and execution. FreeBSD CI mounts the rendezvous, executes the privileged acceptance cases explicitly, and runs both process benchmark targets.

FreeBSD scope qualification uses the filesystem root identity, the effective user and the common kernel monotonic clock. Two independent jails with the same root join the same retained authority. A held FIFO read in one jail prevents physical dispatch from the other under a ceiling of one. After both exit, the authority recovers ownership and the charges survive reopening. The host-to-jail transition fixture verifies the same generation and the charges accrued before entry, then performs and accounts for more work inside the jail.

A jail that exposes the original authority under a different root receives an incompatible-scope error in both direct and Auto modes, and the original journal stays byte-for-byte unchanged. That jail can explicitly create a separate authority in its own tmpfs view, perform work, and retain that charge after reopening. Authority generation creation uses the OS randomness API, so a minimal jail root does not need `/dev/urandom`. Capability-mode entry fences an existing governor and keeps its shared status. The default kernel policy rejects jail entry while the scope holds directory descriptors. Closing those handles permits entry and reopening the compatible authority.

## illumos native acceptance

The shared Unix backend runs on OmniOS r151058 (`omnios-r151058-516f7694c9`), amd64, with Rust nightly 1.101.0 (`07e526db9`, 2026-10-19). Native storage is tmpfs under `/var/run`. Scope checks include the root identity, the zone ID and the zone incarnation that the kernel assigns. The [repository VM helper](../benchmarks/README.md#local-omnios-acceptance-vm) verifies the official cloud-image checksum, boots with UEFI, provisions the toolchain, and transfers public build inputs using USTAR.

The full native run passes 470 tests across 22 suite summaries, with eight ignored subprocess entry points. It includes all three twenty-process cohorts, composed Scan/Tree admission and cancellation, sixty interrupted journal transactions, and interrupted initialization. A descriptor test verifies that closing the original descriptor and an unrelated descriptor does not release the bookkeeping lock that the duplicate holds. That test passes on Linux, FreeBSD and OmniOS.

Native Clippy with warnings denied, rustdoc with warnings denied, and all three coordination Cargo benchmark smoke runs pass. Both process executables cover tiny work, disjoint scans, contention, churn, blocked reads and idle periods. Shared idle rows report zero bookkeeping attempts and zero allocations. `target/benchmarks/omnios-acceptance.log` and `target/benchmarks/omnios-native-checks.log` record the runs. OmniOS CI provisions the rendezvous and runs the three benchmark targets alongside tests, Clippy and rustdoc.

Both native process benchmark executables report aggregate worker user and system CPU deltas through `getrusage(RUSAGE_SELF)`. These resource snapshots run outside the timed wall-clock interval. Linux, FreeBSD and OmniOS smoke runs exercise all six scenarios in both governance modes and both allocator profiles. The reports are in `target/benchmarks/coordination-cpu-{linux,freebsd,omnios}.log`.

The two explicit privileged illumos tests also pass. One test launches UID 65534, performs governed work, verifies retained charges, and rejects a different effective user that tries to join that authority. The other test uses a dedicated linked-package zone and enters it with a live Auto-configured governor in a separate process contract. The old governor is fenced with no local charging and no fallback. Opening a LOFS view of the exact global authority fails and leaves its journal bytes unchanged. The process then creates a zone-local authority, reads a real file under admission, and verifies that the charge survives closing and reopening its handles. The parent verifies that the shared view of the fixture unmounts successfully. `target/benchmarks/omnios-zone-acceptance.log` records the results.

`benchmarks/omnios_zone.sh` provisions this zone for local reproduction and CI. It waits for the SMF minimal filesystem service before it creates the rendezvous, because `zoneadm boot` returns before `/var/run` is mounted and an earlier directory or child mount can be hidden during startup. Every `zlogin` uses `-n`, because the VM action streams its remaining build commands on stdin. Without `-n`, zone setup consumed those commands and CI reported success without running the Rust tests. The streamed-shell regression test reproduces that false success and checks that setup failures still stop the build. The local results above are separate evidence, and the affected CI runs are not acceptance results.

## Windows ownership, security and journal mechanisms

`tests/coordination_windows.rs` exercises the Windows file-handle operations from `src/coordination/windows/handles.rs` and the security checks from `security.rs`. The file histories cover duplicate and inherited ownership, files that are missing, replaced or hard-linked, nonblocking bookkeeping, unrelated handle closes, and writer death while another process retains operation ownership.

The publication fixture kills four separate writers after the invalidation byte, the slot header, the complete payload and the final commit byte. Recovery retains the old state for incomplete payloads and conservatively commits complete payloads. The fixture verifies the same accounting after every journal and anchor handle closes, using the production `Journal` and `Authority` implementations.

Before file creation and recovery used protected-ACL validation, the five file histories passed under Wine 11.20. `target/benchmarks/windows-wine-ownership.log` records that lower-level run. The current native Windows CI runs the full suite on x64 and ARM64, including ACL validation. Wine reconstructs file descriptors without the protected-DACL flag, so the validation rejects them. `target/benchmarks/windows-wine-security.log` records the rejection.

The descriptor-policy test passes both valid file and directory descriptors and ten invalid descriptor cases directly to the descriptor validator. A descriptor that can be read but fails validation produces an invalid-state error, which prevents unavailable-mode fallback. Before joining, the adapter classifies an access-denied result as unavailable, so a file whose ACL prevents the initial data open yields an unavailable result. After joining, either failure fences new work and the governor never switches to process-only mode. A separate test impersonates a duplicate token with the same user SID, verifies that the original captured context is fenced, restores the original token, and verifies access again. Both tests pass under Wine, and `target/benchmarks/windows-wine-descriptors.log` and `windows-wine-impersonation.log` in the same directory record them. Another test opens a scope under an impersonated token and defers a cancellation through held bookkeeping. The cleanup worker settles it under the same token, and the scope stays unfailed. Only native Windows CI runs that test, because under Wine `Scope::open` fails its boot-environment query.

`benchmarks/windows_wine.py` builds the GNU Windows executable with Zig and runs it in an isolated prefix under `target/native/windows`. MSVC cross-compilation and Clippy with warnings denied pass across all targets and features. The native x64 and ARM64 CI suites cover creating and reopening private files and directories, rejecting a broadened ACL without repairing it, and rejecting a non-private existing directory.

Clock conversion and retained-epoch validation pass under Wine. The native clock fixture fails under Wine, because Wine returns `STATUS_INVALID_INFO_CLASS` for the boot-environment query. `target/benchmarks/windows-wine-clock.log` records the run. The implementation uses neither a random generation nor a wall-clock estimate as a substitute. The storage contract test covers remote devices, missing ACL and file-ID capabilities, read-only volumes, unsupported filesystems and malformed filesystem names. The storage API fixture also checks the retained handle after pathname rename and duplication. Both storage tests pass under Wine, including local disk and disk-filesystem device types. `target/benchmarks/windows-wine-storage-native-api.log` records the results.

Four handle-relative path tests pass under Wine. They cover component validation, parent and ancestor replacement exclusion, creation without truncation with duplicated exclusive ownership, and rejection of a real directory junction at both the final component and an ancestor. The creation fixture also verifies that an attribute-only recovery pin can coexist with a live owner and stay open through final-close recovery. `target/benchmarks/windows-wine-relative.log` records the results. Private-object creation and owner recovery use these relative opens, and the retained scope initializer keeps the parent pins across transactions.

`target/benchmarks/windows-wine-integrated-primitives.log` records the complete run of the integrated low-level tests. Ten tests pass, six file histories reject the unprotected DACLs that Wine produces, and the native clock history rejects its unavailable boot query. The one ignored test is the subprocess fixture entry point. The relative-open path reaches the same protected-ACL validation in all six file histories.

The Windows scope initializes and reopens a retained authority, discovers the local application-data directory of the effective user through the OS, recovers final-closed owner slots, and connects to the public shared governor. Native x64 and ARM64 CI execute the tests for generation and charge retention, immediate reclaimed-slot reuse, replacement and configuration disagreement, and actual Scan listing plus lazy reads. The separate known-folder discovery test passes under Wine, and `target/benchmarks/windows-wine-discovery.log` records it. Boot changes publish a signed QPC mapping in the accounting journal. Independent connections reuse the same origin, including after every handle closes. Transactions clamp readings without moving that origin. The production clock math covers counters on either side of the retained time. The regression case with raw time 50,000 and retained time 12,000 failed before the fix and passes after it under Wine, and `target/benchmarks/windows-reboot-regression-{before,after}.log` record both runs. Portable journal tests interrupt every written byte during the first mapping publication and during another boot transition with a reused slot, and compare the complete ownership and accounting before retrying. Native Windows fixtures add simulated boot migration from both counter-only and mapped snapshots, shared origins across independently opened connections, elapsed time after every handle closes, and stale-mapping fencing. The actual reboot was still open at that checkpoint, and the later native run recorded below supplies the reboot evidence. The remaining security/session and crash boundaries require their own acceptance evidence. The twenty-process and resource results are recorded above and in the PR checklist.

Unix and Windows share the operation lifecycle, the error types and the bounded deferred-settlement queue. After the extraction of this shared code, the complete Linux suite passes. Native FreeBSD and OmniOS pass the library tests, the composed-governor tests, the preparation tests and the subprocess acceptance suite. `target/benchmarks/{linux,freebsd,omnios}-shared-client-regression.log` record these results.
