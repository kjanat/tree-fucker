The authority enforces the shared duty budgets, and the journal commits its complete state with the ownership transition. The Linux backend establishes owner-exit evidence using the recorded slot file and a kernel lifetime lock. Native tests cover killed and stopped processes and inherited descriptions. In-memory tests interrupt every byte of authorization and settlement. `tests/coordination_processes/crashes.rs` kills real tmpfs journal writers before invalidation, within the slot header and payload, and after complete-payload and commit writes. It covers preparation, abort, authorization, progress, settlement, and reclamation; validates exact before/after accounting; checks duplicate retry; and distinguishes bookkeeping-owner death from operation-owner exit.

`src/coordination/unix/initialization.rs` launches and kills initializers at seven anchor-write and fourteen initial-journal-write boundaries. Other connections remain excluded until the writer dies. Partial anchor headers are rejected without changing retained files; complete headers recover the same pinned generation and state inode through `Scope::open`. Each recoverable history then performs a real file write/read under shared admission and verifies that its charge survives reconnecting and closing all handles.

`tests/coordinated_governor.rs` exercises real Scan listing and lazy reads, persistent Tree listing, watch registration and shutdown cleanup, reversible admission, lease negotiation, and fail-closed replacement. A Tree open that waits for its root watch fails with the coordination error when the authority is replaced first. Defaults remain process-only; explicit governors created with `HostGovernor::with_coordination` enforce both authorities.

`tests/coordinated_governor/leases.rs` runs the Scan and Tree APIs through an observed filesystem adapter. The local control receives 64 optional operations; the shared authority constrains the first per-child lease to at most twelve. Every resume receives its active grant's allowance, and both modes read each of forty child identities exactly once during the first listing. The Tree fixture also exercises initial capability discovery with no optional operations. It records the first pass separately from periodic baseline work and waits for physical settlement after logical shutdown.

Separate enrichment cases request sizes for forty children. The local governor admits one batch; shared admission splits it into smaller batches. The adapter checks each batch against its active grant and shared physical occupancy, and the fixtures verify all forty returned sizes and exactly one enrichment read per child. Tree verification waits for metadata updates after initial membership completion.

`tests/coordination_policy.rs` exercises mode selection and fallback boundaries. `tests/coordination_install.rs` verifies that installing required coordination protects the default Scan constructor. Composed governor regressions cover confirming metadata reads, failure settlement, cancellation before physical admission, and physical ownership after running cancellation.

The [coordination benchmark baseline](../benchmarks/coordination-baseline.md) records independently launched workers, repeated timing rounds, allocation runs, aggregate process-resource samples, and syscall totals. Both `coordination_processes` Cargo executables have Linux CI smoke runs. The profiler and reproducible commands live in `benchmarks/`; generated fixtures and measurements live under `target/benchmarks`.

The [resource-bound audit](coordination-resource-audit.md) derives participant, operation, domain, journal, cleanup and recovery bounds from the implementation. It records all sixty native aggregate-resource reports from acceptance run 41372711016 on `6b996590e37f05c472ba37db6373e298ef772e18`, including complete-cohort validation and zero work and lock activity in every idle workload; the timing executable does not instrument allocations. Per-connection/path-depth costs and retained allocator capacity remain distinct from configured ledger limits.

Composed retries distinguish lock/physical contention from refillable budget denials. Shared quarantine reaches Scan during both preparation and start: traversal emits `Unlisted` for the affected domain and continues with healthy siblings; lazy reads return `Stuck`. A shared minimum above the caller ceiling returns `ResourceLimited`, including during Scan bootstrap and initial or resumed Tree command admission. `tests/coordinated_governor/tree_denials.rs` covers Refresh and Load at both admission stages and verifies that a coalesced command with sufficient remaining budget continues after an older command is rejected. On Linux, the same file has a peer hold stuck work on a shared mount domain. A queued Tree job denied at start and a suspended job denied at resumption are both cancelled, release their preparations, and leave the batch free for a healthy domain. Their Refresh commands stay open until the peer settles and complete when the Tree timer fires at the shared quarantine retry deadline. Tree domain health reports `StuckWorker` for the mount domain during the peer's quarantine and clears after the peer settles. In `tests/tree.rs`, `a_tree_queued_behind_host_capacity_wakes_when_another_holder_releases_it` releases a directly held host slot and asserts that the queued Refresh completes without advancing time. In `tests/resource_safety.rs`, `a_governor_denial_changes_no_obligation_cursor_barrier_or_retry_state` admits a foreground Refresh in the dispatch cycle that finds the background bucket in debt. `tests/coordinated_governor/denials.rs` verifies these outcomes without permitting a retry wait. Its `shared_quarantine_retry_doubles_to_its_cap_and_resets_on_admission` asserts retry deadlines of 10, 20, 40, 80, 160, 320, and 640 ms, then 1 s twice, across consecutive quarantine denials, and no deadline after the next admission starts and releases. While the domain backs off, an admission with the bookkeeping lock held is refused with `StuckWorker` and makes no shared attempt, and an admission on another domain at the same time succeeds. Its `busy_shared_denial_keeps_the_quarantine_health_report_and_delay` reaches a 40 ms quarantine delay and attempts after that deadline with the bookkeeping lock held. It asserts a `Coordination` denial, a 3 ms retry, and `StuckWorker` domain health, and that the next attempt after the lock retry receives a quarantine denial with an 80 ms delay. Authority tests distinguish refillable debt from insufficient ceilings for bootstrap and known domains, retain capacity-capped pricing, and preserve the cleanup exemption. The twenty-process Scan cohort records quarantine before explicitly retrying lazy reads after owner settlement. Retry tests cover bounded backoff, stable upcoming deadlines, expired hints, reset after progress, and zero local charging during denied starts or preparations. Measured retry changes reduce contention and churn latency while increasing contention CPU; the benchmark baseline records both effects.

## Composed acquisition under bookkeeping contention

`tests/coordination_acquisition.rs` exercises the public `HostGovernor` through the production native authority. A controller holds the actual bookkeeping lock and loads the journal under that exclusion. Comparing the complete authority before and after local actions checks that provisional rollback, completion, and duplicate release cannot change shared ownership before a durable commit.

The acquisition matrix covers nine boundaries with background/foreground priority, zero/four optional operations, and bootstrap/known-domain reservations: 72 histories. It includes local preparation denial, dropping local preparation, failed public commit, cancelling shared preparation, local memory rejection at start, a busy shared start, a full shared physical ceiling, physical completion, and completion after a cost report. Contended calls execute on deadline-bounded worker threads; local rejection checks that shared authorization was never attempted, and a busy start checks one native attempt plus rollback of the local physical hold.

Each boundary now checks the expected summed local preparations, reserved duration, physical occupancy, cumulative charge and surcharge, together with shared preparations, physical occupancy, bootstrap reservation, withheld debt, surcharge and pending settlement count. Shared cumulative charges are bounded by the authorized reservations and a surrounding native-clock interval; a history that never authorizes work must charge exactly zero. Local preparation denial and duplicate start run while bookkeeping is held and must make no native attempt. Duplicate release preserves the same accounting and pending count. The clock bound uses `CLOCK_MONOTONIC` on Unix and integer performance-counter conversion on Windows, avoiding an assumption that Rust `Instant` uses the authority clock on macOS.

Another 24 histories exercise every release order for three participants with both priorities and lease sizes. One operation has physical ownership and two remain provisional. Each application drops its final client reference after queuing completion or abort, while the journal and all three owner lifetimes remain retained until those updates commit. Tree shutdown also runs with bookkeeping held: logical cancellation retains physical ownership, actual completion releases local capacity, and deferred settlement retains the shared slot until commit. Reproduce all 97 histories with `cargo test --all-features --test coordination_acquisition`; the target is included in the native Windows and Unix CI suites.

Windows also runs the common `coordinated_governor` suite, including negotiated initial/resumed listing leases, enrichment allowances, persistent Tree watch/shutdown cleanup, and local/shared start denial. Its directory-rename fencing case remains Unix-specific because live Windows handles prevent that rename; the native Windows replacement test checks that stronger pinning behavior directly.

Local preparation has no durable publication or cross-process replay: process exit discards that process-local mutex state. A successful composed retry uses a fresh operation identity rather than replaying a previous public preparation. Lease narrowing is negotiated before the composed preparation commits; the binding does not call the native `Prepared::narrow` API. Listing and enrichment tests in `coordinated_governor/leases.rs` verify the actual grant delivered to each initial/resumed batch and exactly one read per requested child.

Over-reporting beyond a grant is outside the valid event matrix. Section 15.3 requires adapters to honor the per-child lease, and the shared protocol rejects malformed cumulative counts. Fencing that connection is intentional; clamping its operation count would hide an adapter-contract violation. Elapsed-time overshoot remains valid and is charged separately.

`one_and_three_participants_produce_the_expected_accounting_history` in `coordinated_governor/histories.rs` compares the same 28 boundaries with three logical actors sharing one governor or using three governors. Both traces must match a separately written expected trace. The stream includes background success, foreground failure, preparation/drop, local memory denial, ordinary bootstrap denial, budget-exempt watch cleanup, shared physical denial/retry, deferred settlement and duplicate start/release. It compares summed local preparations, reserved duration, physical occupancy, charge and surcharge against shared preparations, physical occupancy, cumulative charge/surcharge, bootstrap reservation, withheld debt and pending settlement count at every boundary. Only participant count and per-process bucket levels are excluded from equality because they differ by construction; native refill levels are not used as a deterministic oracle.

The equivalence fixture prices bootstrap work at one hour and gives each completed operation that same duration on the caller's manual clock. Thus local estimator samples stay identical across both topologies, while real native occupancy remains below each reservation. A prepared two-estimate holder fills the shared bootstrap cap: ordinary foreground admission is denied, then watch cleanup succeeds and raises the held reservation to three estimates. This proves cleanup's exemption while another allowance is exhausted, including when the earlier denial belongs to the same participant. Under held bookkeeping, completion changes local ownership but leaves one shared physical record and one pending settlement; draining retires both exactly once.

`coordinated_governor/lifecycle.rs` checks the public Scan and Tree completion paths. `cancelling_a_running_composed_scan_listing_keeps_both_slots_until_physical_completion` uses a physical-start barrier and retains both slots after logical cancellation until the adapter returns. A session that completes successfully despite cancellation owes no surcharge; a session that reports cancellation owes exactly one surcharge to each authority under section 13.1. `cancelling_a_scan_waiting_for_peer_physical_capacity_retires_its_preparations_uncharged` proves no directory read occurred, retires both preparations, and leaves the peer's physical ownership and exact committed charge intact.

`dropping_the_last_governor_with_started_work_settles_one_shared_failure` exercises final binding destruction with physical ownership still held. All participants and holds retire, one shared failure surcharge remains, and a later successful participant does not repeat it. `a_failed_foreground_tree_refresh_is_surcharged_once_by_each_authority` asserts the dispatched grant's foreground origin and both surcharges through duplicate release and shutdown. `a_failed_scan_lazy_read_is_surcharged_once_by_each_authority` keeps both surcharges unchanged through subsequent successful reads and Scan drop. The earlier background Tree failure/lost-worker test also checks both authorities' surcharge totals.

## Portable native process cohorts

`tests/coordination_cohorts.rs` runs the same three twenty-process histories on Linux, FreeBSD, illumos, macOS, and Windows. Each independent process joins the authority and blocks in a kernel pipe read inside an admitted callback. An independently locked counter records actual callback entry and completion; it does not use ledger occupancy as its oracle. The controller holds two calls past the stuck threshold, checks that no third callback entered, releases every pipe, and verifies that all participants and reservations retire while the generation and charges survive reopening every authority handle.

The cohorts exercise native Bootstrap/LazyRead/WatchRelease operations, real `Scan::read`, and mixed Scan bootstrap, lazy reads, and Tree watch cleanup. A companion crash history kills one of two held owners, verifies that only its slot is recovered, and starts a replacement while the other process remains blocked. That history runs through each of the three API fixtures. Child processes are killed and waited if a parent assertion fails; readiness and completion have bounded deadlines. These tests run as part of the full native CI suite. Reproduce with `cargo test --all-features --test coordination_cohorts`.

## FreeBSD native acceptance

The shared Unix backend runs on FreeBSD 15.0-RELEASE-p14 amd64 under QEMU/KVM, using an administrator-mounted tmpfs and Rust nightly 1.101.0 (2026-10-19). The full suite and four explicit privileged acceptance cases pass after adding compatible jail support. These include same-root jail contention, host-to-jail charge retention, different-root rejection and local authority creation, and effective-user isolation. Native Clippy with warnings denied and rustdoc with warnings denied pass. The complete run is recorded in `target/benchmarks/freebsd-jail-full.log`.

The process histories include all three twenty-application cohorts under a shared physical ceiling of two, inherited owner descriptions, stopped/killed owners, retained debt, and sixty interrupted journal transactions. Effective-user testing launches a process as UID 65534, verifies a real admitted file read and retained charge, and checks that another effective user cannot join its private scope.

Native `coordination`, `coordination_processes`, and `coordination_processes_alloc` smoke runs pass. The process benches cover all six scenarios under local and shared governance; idle workers report zero bookkeeping accesses and zero allocations. The post-jail-support benchmark run is recorded in `target/benchmarks/freebsd-jail-bench.log`. The [repository VM helper](../benchmarks/README.md#local-freebsd-acceptance-vm) reproduces provisioning and execution. FreeBSD CI mounts the rendezvous, executes the privileged acceptance cases explicitly, and runs both process benchmark targets.

FreeBSD scope qualification uses filesystem root identity, effective user, and the common kernel monotonic clock. Two independent jails with the same root join the same retained authority: a held FIFO read in one jail prevents physical dispatch from the other under a ceiling of one. After both exit, ownership is recovered and charges survive reopening. The host-to-jail transition fixture verifies the same generation and charges accrued before entry, then performs and accounts for more work inside the jail.

A jail exposing the original authority under a different root receives an incompatible-scope error in both direct and Auto modes, leaving the original journal byte-for-byte unchanged. It can explicitly create a separate authority in its own tmpfs view, perform work, and retain that charge after reopening. Authority generation creation uses the OS randomness API, so a minimal jail root does not need `/dev/urandom`. Capability-mode entry still fences an existing governor and preserves its shared status instead of downgrading it. The default kernel policy rejects jail entry while the scope holds directory descriptors; closing those handles permits entry and reopening the compatible authority.

## Linux namespace and listing-resume acceptance

`tests/coordination_namespaces.rs` runs five histories inside isolated Linux user namespaces. It changes only a worker's IPC namespace while a real FIFO read owns physical capacity, verifies rejection through both the native API and an Auto-configured governor, and then restores that worker's original namespace before settlement. Separate user, IPC, and time namespace processes cannot join the existing authority. The time case applies a real 3,600-second monotonic offset; rejected joins leave the authority file byte-for-byte unchanged. A `CLONE_NEWTIME` case verifies that selecting a namespace for future children leaves the current thread's authority usable while rejecting its differently qualified child.

The namespace suite runs explicitly in Linux CI because namespace creation requires kernel permission. The listing regression reproduced three empty resumes between useful per-child leases in an eight-lease Tree history. Scan and Tree now request operations on the next lease when the current session performed per-child work, as well as when it made no progress. This preserves observed work requirements before domain capabilities have been published. The observed-filesystem fixture rejects any zero-operation resume after per-child work begins, checks all negotiated allowances, and still verifies exactly one identity read per child. All four Scan/Tree listing and enrichment fixtures pass on Linux and native FreeBSD after the change.

The streamed-shell regression reproduces that false success and checks that setup failures still stop the build. The earlier local results above remain separate evidence; affected CI runs are not acceptance results.
