The authority enforces the shared duty budgets, and the journal commits its complete state with the ownership transition. The Linux backend establishes owner-exit evidence using the recorded slot file and a kernel lifetime lock. Native tests cover killed and stopped processes and inherited descriptions. In-memory tests interrupt every byte of authorization and settlement. `tests/coordination_processes/crashes.rs` kills real tmpfs journal writers before invalidation, within the slot header and payload, and after complete-payload and commit writes. It covers preparation, abort, authorization, progress, settlement, and reclamation; validates exact before/after accounting; checks duplicate retry; and distinguishes bookkeeping-owner death from operation-owner exit.

`src/coordination/unix/initialization.rs` launches and kills initializers at seven anchor-write and fourteen initial-journal-write boundaries. Other connections remain excluded until the writer dies. Partial anchor headers are rejected without changing retained files; complete headers recover the same pinned generation and state inode through `Scope::open`. Each recoverable history then performs a real file write/read under shared admission and verifies that its charge survives reconnecting and closing all handles.

`tests/coordinated_governor.rs` exercises real Scan listing and lazy reads, persistent Tree listing, watch registration and shutdown cleanup, reversible admission, lease negotiation, and fail-closed replacement. Defaults remain process-only; explicit governors created with `HostGovernor::with_coordination` enforce both authorities.

`tests/coordinated_governor/leases.rs` runs the Scan and Tree APIs through an observed filesystem adapter. The local control receives 64 optional operations; the shared authority constrains the first per-child lease to at most twelve. Every resume receives its active grant's allowance, and both modes read each of forty child identities exactly once during the first listing. The Tree fixture also exercises initial capability discovery with no optional operations. It records the first pass separately from periodic baseline work and waits for physical settlement after logical shutdown.

Separate enrichment cases request sizes for forty children. The local governor admits one batch; shared admission splits it into smaller batches. The adapter checks each batch against its active grant and shared physical occupancy, and the fixtures verify all forty returned sizes and exactly one enrichment read per child. Tree verification waits for metadata updates after initial membership completion.

`tests/coordination_policy.rs` exercises mode selection and fallback boundaries. `tests/coordination_install.rs` verifies that installing required coordination protects the default Scan constructor. Composed governor regressions cover confirming metadata reads, failure settlement, cancellation before physical admission, and physical ownership after running cancellation.

The [coordination benchmark baseline](../benchmarks/coordination-baseline.md) records independently launched workers, repeated timing rounds, allocation runs, aggregate process-resource samples, and syscall totals. Both `coordination_processes` Cargo executables have Linux CI smoke runs. The profiler and reproducible commands live in `benchmarks/`; generated fixtures and measurements live under `target/benchmarks`.

Composed retries distinguish lock/physical contention from budget and quarantine denials. Tests cover bounded backoff, stable upcoming deadlines, expired hints, reset after progress, and zero local charging during denied starts or preparations. Measured retry changes reduce contention and churn latency while increasing contention CPU; the benchmark baseline records both effects.

## FreeBSD native acceptance

The shared Unix backend runs on FreeBSD 15.0-RELEASE-p14 amd64 under QEMU/KVM, using an administrator-mounted tmpfs and Rust nightly 1.101.0 (2026-10-19). The full suite and four explicit privileged acceptance cases pass after adding compatible jail support. These include same-root jail contention, host-to-jail charge retention, different-root rejection and local authority creation, and effective-user isolation. Native Clippy with warnings denied and rustdoc with warnings denied pass. The complete run is recorded in `target/benchmarks/freebsd-jail-full.log`.

The process histories include all three twenty-application cohorts under a shared physical ceiling of two, inherited owner descriptions, stopped/killed owners, retained debt, and sixty interrupted journal transactions. Effective-user testing launches a process as UID 65534, verifies a real admitted file read and retained charge, and checks that another effective user cannot join its private scope.

Native `coordination`, `coordination_processes`, and `coordination_processes_alloc` smoke runs pass. The process benches cover all six scenarios under local and shared governance; idle workers report zero bookkeeping accesses and zero allocations. The post-jail-support benchmark run is recorded in `target/benchmarks/freebsd-jail-bench.log`. The [repository VM helper](../benchmarks/README.md#local-freebsd-acceptance-vm) reproduces provisioning and execution. FreeBSD CI mounts the rendezvous, executes the privileged acceptance cases explicitly, and runs both process benchmark targets.

FreeBSD scope qualification uses filesystem root identity, effective user, and the common kernel monotonic clock. Two independent jails with the same root join the same retained authority: a held FIFO read in one jail prevents physical dispatch from the other under a ceiling of one. After both exit, ownership is recovered and charges survive reopening. The host-to-jail transition fixture verifies the same generation and charges accrued before entry, then performs and accounts for more work inside the jail.

A jail exposing the original authority under a different root receives an incompatible-scope error in both direct and Auto modes, leaving the original journal byte-for-byte unchanged. It can explicitly create a separate authority in its own tmpfs view, perform work, and retain that charge after reopening. Authority generation creation uses the OS randomness API, so a minimal jail root does not need `/dev/urandom`. Capability-mode entry still fences an existing governor and preserves its shared status instead of downgrading it. The default kernel policy rejects jail entry while the scope holds directory descriptors; closing those handles permits entry and reopening the compatible authority.

## Linux namespace and listing-resume acceptance

`tests/coordination_namespaces.rs` runs five histories inside isolated Linux user namespaces. It changes only a worker's IPC namespace while a real FIFO read owns physical capacity, verifies rejection through both the native API and an Auto-configured governor, and then restores that worker's original namespace before settlement. Separate user, IPC, and time namespace processes cannot join the existing authority. The time case applies a real 3,600-second monotonic offset; rejected joins leave the authority file byte-for-byte unchanged. A `CLONE_NEWTIME` case verifies that selecting a namespace for future children leaves the current thread's authority usable while rejecting its differently qualified child.

The namespace suite runs explicitly in Linux CI because namespace creation requires kernel permission. Local reproduction is `cargo test --test coordination_namespaces namespace_histories -- --ignored --nocapture`; its recorded run is `target/benchmarks/linux-namespace-acceptance.log`. The existing publication and physical-owner fixtures continue to exercise descriptor lifetime and participant death independently of namespace changes.

The listing regression reproduced three empty resumes between useful per-child leases in an eight-lease Tree history. Scan and Tree now request operations on the next lease when the current session performed per-child work, as well as when it made no progress. This preserves observed work requirements before domain capabilities have been published. The observed-filesystem fixture rejects any zero-operation resume after per-child work begins, checks all negotiated allowances, and still verifies exactly one identity read per child. All four Scan/Tree listing and enrichment fixtures pass on Linux and native FreeBSD after the change.

## illumos native acceptance

The shared Unix backend runs on OmniOS r151058 (`omnios-r151058-516f7694c9`), amd64, with Rust nightly 1.101.0 (`07e526db9`, 2026-10-19). Native storage is tmpfs under `/var/run`. Scope checks include root identity, zone ID, and the kernel's zone incarnation. The [repository VM helper](../benchmarks/README.md#local-omnios-acceptance-vm) verifies the official cloud-image checksum, boots with UEFI, provisions the toolchain, and transfers public build inputs using USTAR.

The full native run passes 470 tests across 22 suite summaries, with eight ignored subprocess entry points. It includes all three twenty-process cohorts, composed Scan/Tree admission and cancellation, sixty interrupted journal transactions, and interrupted initialization. A new descriptor test verifies that closing the original and an unrelated descriptor does not release the duplicate's bookkeeping lock. That test passes on Linux, FreeBSD, and OmniOS.

Native Clippy with warnings denied, rustdoc with warnings denied, and all three coordination Cargo benchmark smoke runs pass. Both process executables cover tiny work, disjoint scans, contention, churn, blocked reads, and idle periods. Shared idle rows report zero bookkeeping attempts and zero allocations. The runs are recorded in `target/benchmarks/omnios-acceptance.log` and `target/benchmarks/omnios-native-checks.log`. OmniOS CI provisions the rendezvous and runs the three benchmark targets alongside tests, Clippy, and rustdoc.

Both native process benchmark executables now report aggregate worker user and system CPU deltas through `getrusage(RUSAGE_SELF)`. These resource snapshots run outside the timed wall-clock interval. Linux, FreeBSD, and OmniOS smoke runs exercise all six scenarios in both governance modes and both allocator profiles; reports are retained as `target/benchmarks/coordination-cpu-{linux,freebsd,omnios}.log`.

The two explicit privileged illumos tests also pass. One launches UID 65534, performs governed work, verifies retained charges, and rejects a different effective user joining that authority. The other uses a dedicated linked-package zone and enters it with a live Auto-configured governor in a separate process contract. The old governor is fenced without local charging or fallback. A LOFS view of the exact global authority is rejected without changing its journal bytes. The process then creates a zone-local authority, reads a real file under admission, and verifies that the charge survives closing and reopening its handles. The parent verifies successful unmount of the fixture's shared view. Results are recorded in `target/benchmarks/omnios-zone-acceptance.log`.

`benchmarks/omnios_zone.sh` provisions this zone for local reproduction and CI. It waits for SMF's minimal filesystem service before creating the rendezvous: `zoneadm boot` returns before `/var/run` is mounted, so an earlier directory or child mount can be hidden during startup.

## macOS port and native acceptance wiring

`src/coordination/macos.rs` implements root-qualified retained tmpfs coordination through the shared Unix backend. The public governor policy, diagnostics, domain accounting, subprocess histories, and all three coordination Cargo benches compile for `aarch64-apple-darwin` and `x86_64-apple-darwin` with Clippy warnings denied. FIFO fixtures use a shared `mkfifo` helper because Rustix does not expose its `mkfifoat` wrapper on Darwin.

The macOS workflow mounts case-sensitive tmpfs at the standard rendezvous, runs the complete native suite on ARM64 and Intel, explicitly launches privileged root-transition acceptance, and runs both independent-process benchmark smoke targets. The dedicated sandbox subprocess checks pre-join fallback and post-join fencing without changing the journal or charging local work. Current-head macOS CI passes on both architectures. Native sleep/wake and resource acceptance remain outstanding.

The shared changes pass the Linux full suite and focused native FreeBSD/OmniOS unit and process suites, including initialization crashes and all three twenty-process cohorts. Logs are recorded in `target/benchmarks/linux-macos-port-regression.log`, `freebsd-port-regression.log`, and `omnios-port-regression.log` under the same benchmark directory.

## Solaris lifetime investigation

`tests/coordination_socket_lifetime.rs` checks a bound Unix datagram endpoint without an accept loop or probe messages. It verifies duplicate retention, fork inheritance through original-owner death, final-close behavior, and an outstanding connected probe. All three histories pass on Linux, FreeBSD, and OmniOS. The test compiles for Solaris; native Solaris execution is unavailable. Solaris authority integration and bookkeeping exclusion remain outstanding.

## Windows ownership, security, and journal primitives

`tests/coordination_windows.rs` exercises the Windows file primitives from `src/coordination/windows/handles.rs` and the security checks from `security.rs`. The file histories cover duplicate and inherited ownership, missing/replaced/hard-linked files, nonblocking bookkeeping, unrelated handle closes, and writer death while another process retains operation ownership.

The publication fixture kills four separate writers after the invalidation byte, slot header, complete payload, and final commit byte. Recovery retains the old state for incomplete payloads and conservatively commits complete payloads. It verifies the same accounting after every journal and anchor handle closes, using the production `Journal` and `Authority` implementations.

Before protected-ACL validation was connected to file creation and recovery, the five file histories passed under Wine 11.20; that lower-level run is recorded in `target/benchmarks/windows-wine-ownership.log`. The current native Windows CI runs the full suite on x64 and ARM64, including ACL validation. Wine reconstructs file descriptors without retaining the protected-DACL flag and is rejected, as recorded in `target/benchmarks/windows-wine-security.log`.

The current descriptor-policy test passes both valid file/directory descriptors and ten invalid descriptor cases. Unsafe descriptors produce invalid-state errors, preventing unavailable-mode fallback. A separate test impersonates a duplicate token with the same user SID, verifies that the original captured context is fenced, then restores the original token and verifies access again. Both pass under Wine; their logs are `target/benchmarks/windows-wine-descriptors.log` and `windows-wine-impersonation.log` in the same directory.

The repository's `benchmarks/windows_wine.py` builds the GNU Windows executable with Zig and runs it in an isolated prefix under `target/native/windows`. MSVC cross-compilation and Clippy with warnings denied pass across all targets and features. The native x64 and ARM64 CI suites cover creating/reopening private files and directories, rejecting a broadened ACL without repairing it, and rejecting a non-private existing directory.

Clock conversion and retained-epoch validation pass under Wine. The native clock fixture fails because Wine returns `STATUS_INVALID_INFO_CLASS` for the boot-environment query; the run is recorded in `target/benchmarks/windows-wine-clock.log`. The implementation does not substitute a random generation or wall-clock estimate. The storage contract test covers remote devices, missing ACL/file-ID capabilities, read-only volumes, unsupported filesystems, and malformed filesystem names. The storage API fixture also checks the retained handle after pathname rename and duplication. Both storage tests pass under Wine, including local disk and disk-filesystem device types; results are recorded in `target/benchmarks/windows-wine-storage-native-api.log`.

Four handle-relative path tests pass under Wine: component validation, parent/ancestor replacement exclusion, non-truncating creation with duplicated exclusive ownership, and rejection of a real directory junction at both the final component and an ancestor. The creation fixture also verifies that an attribute-only recovery pin can coexist with a live owner and remain open through final-close recovery. Results are recorded in `target/benchmarks/windows-wine-relative.log`. Private-object creation and owner recovery use these relative opens; the retained scope initializer keeps the parent pins across transactions.

The complete integrated primitive run is recorded in `target/benchmarks/windows-wine-integrated-primitives.log`: ten tests pass, six file histories reject Wine's unprotected DACLs, and the native clock history rejects its unavailable boot query. The one ignored test is the subprocess fixture entry point. The new relative-open path reaches the same protected-ACL validation in all six file histories.

The Windows scope initializes and reopens a retained authority, discovers the effective user's local application-data directory through the OS, recovers final-closed owner slots, and connects to the public shared governor. Native x64 and ARM64 CI execute the tests for generation/charge retention, immediate reclaimed-slot reuse, replacement/configuration disagreement, and actual Scan listing plus lazy reads. The separate known-folder discovery test passes under Wine, recorded in `target/benchmarks/windows-wine-discovery.log`. Boot changes rebase QPC at the retained authority timestamp without refilling downtime, and transactions clamp to the latest committed time; native CI passes a simulated prior-boot anchor test that checks generation/debt retention. Actual reboot, twenty-process Windows contention, end-to-end crash/session transitions, and native resource measurements remain outstanding.

The operation lifecycle, error types, and bounded deferred-settlement queue are shared between Unix and Windows. After this extraction, the complete Linux suite passes. Native FreeBSD and OmniOS pass library tests, composed-governor tests, preparation tests, and the subprocess acceptance suite. These results are recorded in `target/benchmarks/{linux,freebsd,omnios}-shared-client-regression.log`.
