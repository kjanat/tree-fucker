# Shared coordination requirements audit

This is the requirement-to-evidence map for PR #9 and the in-scope portion of [issue #1](https://github.com/kjanat/tree-fucker/issues/1). The design requirements in that issue and [the protocol extension](coordination.md) remain normative. Test names below identify executable checks, not claims that all possible executions were explored. The [acceptance record](coordination-acceptance.md) records exact tested revisions and native runs.

The feature stays opt-in. ProcessOnly is the default, snapshots and credentials remain local, and no release decision enabling Auto by default is part of this PR. The cooperating scope is the validated user/security, namespace, storage and clock boundary in [the platform contract](coordination-platforms.md). Neither same-user cooperation nor a shared physical ceiling enforces limits on an uncooperative process or proves that a remote server stopped executing an abandoned request.

## Required histories and invariants

The composed matrix accounts for preparation, start authorization, physical execution, completion, deferred publication, cancellation/drop and replay. The [native recovery matrix](coordination-acceptance.md#native-recovery-and-retained-accounting-matrix) accounts for initialization, two recoverers, join/recovery serialization, replacement, inherited ownership and final-close retention. Together these address #16 and #17 without treating primitive tests as proof of integrated scheduler behavior.

| Required history                                                               | Evidence                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No physical release from cancellation, timeout, missing input or stopped owner | Running cancellation and shutdown tests; native suspended-owner fixtures; held owner survives writer death; stuck-accounting tests retain physical occupancy                                                                             |
| Completion before settlement, then every connection exits                      | `completion_without_settlement_survives_every_connection_closing`; Windows/Unix writer-kill and replay histories; one conservative recovery surcharge                                                                                    |
| Reused participant slot cannot release a new owner's work                      | `recovery_preserves_a_reused_live_slot_and_join_respects_bookkeeping`; protocol incarnation and stale-completion tests; native slot file identity validation                                                                             |
| Restart, churn and final participant close do not reset debt                   | `actual_debt_survives_closing_every_handle_and_reopening`, Windows retained-generation test, native churn workload and twenty-process create/open histories                                                                              |
| No old and new authority can both authorize through replacement                | `removing_the_anchor_cannot_reset_retained_accounting`, state/directory/owner replacement tests, partial anchor rejection, unpublished-only initialization, generation and journal identity checks                                       |
| Healthy work can proceed alongside a stuck domain                              | `overdue_shared_work_keeps_healthy_domains_admissible_until_settlement`, per-domain/per-origin denial regressions, queued/resumed Tree quarantine tests; no fixed completion deadline is promised                                        |
| Mixed compatible copies and incompatible wire versions                         | Independent executable processes join the same version-independent rendezvous; checked protocol/header decoders reject incompatible state. Compatibility concerns the specified wire protocol, not arbitrary older crate releases        |
| Full/corrupt/incomplete state and missed notifications                         | Capacity and every-byte corruption tests; initialization publication kills; foreground/background retry regressions and governor-change wake tests. Notifications are hints; scheduled retry is sufficient when a peer supplies no input |
| Weak/reused domain identity and incompatible namespaces                        | `shared_identity_is_namespace_qualified_and_private_numbers_do_not_match`; Linux namespace and mount/domain transition tests; unsupported identity remains participant-private under the aggregate envelope                              |
| Foreground failures, cleanup exceptions and one/many participant equivalence   | The 28-point composed history checks each expected accounting state with one and three governors; failure settlement tests; `cleanup_exempts_duty_but_never_exempts_physical_capacity`                                                   |

Local/shared accounting are separate ledgers for the same operation. The composed history compares holds, occupancy, cumulative charges, failure surcharges and pending settlement at each meaningful boundary. Native elapsed occupancy is checked against clock bounds; real scheduling variance is not asserted to be bit-identical between separate executions.

`cancelled_shared_preparations_refund_only_the_unstarted_command_lease` covers initial and resumed Refresh/Load work. It verifies that a full reversible hold cannot exhaust a command, cancellation returns exactly the current preparation's hold, previous physical leases remain charged, and the same command completes after capacity returns. Existing peer-quarantine tests exercise the scheduler paths that cancel those preparations.

## Report-audit decisions and deferred scope

The earlier report audit's four open design questions have concrete dispositions in the base RFC:

- Portable metadata exposes optional permission bits. Native ACLs, effective-access decisions and credentials remain adapter-owned; enumeration does not silently add ACL requests (`fs.rs` metadata contract and RFC permission model).
- A subtree rescan dirties represented loaded descendants without forcing excluded/unloaded subtrees into memory. `subtree_rescan_repairs_descendants_and_preserves_watcher_health` checks repair and watcher health.
- Dropped hints start reconciliation recovery and publish the dropped count/coverage state without restarting a healthy watcher. `dropped_hints_report_recovery_without_restarting_a_healthy_watcher` checks saturation and subsequent repair.
- Protocol-native implementations use the existing filesystem adapter boundary, declare identity/capabilities and account for every physical request. Bundling SMB/WebDAV/FTP clients or their credential pools is outside the core contract; no nominal client implementation is advertised.

Shared observations, shared snapshots, exactly-once scans across processes, global RSS enforcement, automatic scope replacement and enabling Auto by default are outside this PR. The protocol deliberately rejects unsafe replacement instead of attempting an unimplemented generation handoff. Solaris shared coordination remains enforced as unavailable under #19. Physical Mac sleep/wake remains unverified under #20: the source/ownership review found no permission reclamation based on elapsed time, but hosted execution does not establish a physical sleep transition. These exclusions remain visible in the platform contract and do not close parent issue #1.
