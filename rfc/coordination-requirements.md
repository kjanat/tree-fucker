# Shared coordination requirements audit

This document maps each requirement of PR #9 and the in-scope portion of [issue #1](https://github.com/kjanat/tree-fucker/issues/1) to its evidence. The design requirements in that issue and [the protocol extension](coordination.md) are normative. Each test name below identifies an executable check. A test name makes no claim that the test explored every possible execution. The [acceptance record](coordination-acceptance.md) lists the exact tested revisions and native runs.

The feature is opt-in. ProcessOnly is the default, snapshots and credentials stay local, and this PR makes no release decision to enable Auto by default. The cooperating scope is the validated user/security, namespace, storage and clock boundary in [the platform contract](coordination-platforms.md). Same-user cooperation and a shared physical ceiling impose no limits on an uncooperative process. They also give no proof that a remote server stopped executing an abandoned request.

## Required histories and invariants

The composed matrix accounts for preparation, start authorization, physical execution, completion, deferred publication, cancellation/drop and replay. The [native recovery matrix](coordination-acceptance.md#native-recovery-and-retained-accounting-matrix) accounts for initialization, two recoverers, join/recovery serialization, replacement, inherited ownership and final-close retention. Together these address #16 and #17. Unit tests of the native mechanisms give no proof of integrated scheduler behavior.

| ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cancellation, timeout, missing input and a stopped owner release no physical capacity | Running cancellation and shutdown tests; native suspended-owner fixtures; held owner survives writer death; stuck-accounting tests retain physical occupancy                                                                                          |
| Completion before settlement, then every connection exits                             | `completion_without_settlement_survives_every_connection_closing`; Windows/Unix writer-kill and replay histories; one conservative recovery surcharge                                                                                                 |

The local and shared accounts are separate ledgers for the same operation. The composed history compares holds, occupancy, cumulative charges, failure surcharges and pending settlement at each meaningful boundary. The native tests check elapsed occupancy against clock bounds. Separate executions differ in real scheduling, so the tests do not require bit-identical timing.

`cancelled_shared_preparations_refund_only_the_unstarted_command_lease` covers initial and resumed Refresh/Load work. It verifies four facts. A full reversible hold cannot exhaust a command. Cancellation returns exactly the current preparation's hold. Previous physical leases remain charged. The same command completes after capacity returns. The existing peer-quarantine tests exercise the scheduler paths that cancel those preparations.

Scan also refunds its provisional ceiling charge when the governor refuses to start a reversible preparation. `scan_skips_shared_quarantine_between_preparation_and_start` checks that a quarantined subtree leaves healthy siblings admissible under a finite ceiling and that reported admission equals authorized local charges. `repeated_lazy_read_start_quarantine_spends_no_scan_allowance` repeats the start refusal three times and checks that the allowance is unchanged each time. It then verifies that a successful read spends the allowance. Committed process-only admissions and physically authorized work keep their charges.

## Report-audit decisions and deferred scope

The base RFC gives each of the four open design questions from the earlier report audit a concrete disposition:

- Portable metadata exposes optional permission bits. Adapters own native ACLs, effective-access decisions and credentials, and enumeration adds no ACL requests (`fs.rs` metadata contract and RFC permission model).
- A subtree rescan dirties represented loaded descendants and leaves excluded or unloaded subtrees out of memory. `subtree_rescan_repairs_descendants_and_preserves_watcher_health` checks repair and watcher health.
- Dropped hints start reconciliation recovery and publish the dropped count and coverage state. The healthy watcher keeps running. `dropped_hints_report_recovery_without_restarting_a_healthy_watcher` checks saturation and subsequent repair.
- Protocol-native implementations use the existing filesystem adapter boundary, declare identity and capabilities, and account for every physical request. The core contract excludes bundled SMB, WebDAV and FTP clients and their credential pools, and the project advertises no nominal client implementation.

This PR excludes shared observations, shared snapshots, exactly-once scans across processes, global RSS enforcement, automatic scope replacement and enabling Auto by default. The protocol rejects unsafe replacement because the generation handoff is unimplemented. Solaris shared coordination stays enforced as unavailable under #19. Physical Mac sleep/wake stays unverified under #20. The source and ownership review found no permission reclamation based on elapsed time, and hosted execution cannot produce a physical sleep transition. The platform contract lists these exclusions, and they do not close parent issue #1.
